# 1.0.0

The first stable, versioned public release of `isoperiod`. Developed within UKCEH's FDRI programme, the library
provides ISO 8601 period and duration arithmetic for environmental timeseries data, making the grid a timeseries is
measured on (i.e. its sampling resolution and periodicity) an object that can be compared and validated.

## Features

### Core

- **`Period`** - the central object representing a repeating period that splits the timeline into consecutive, numbered
intervals, covering both fixed-length (microsecond through to multi-day) and calendar-aligned (monthly, annual)
periods.
- Built from an ISO 8601 duration string (`"PT15M"`, `"P1D"`, `"P1Y"`), from a named unit (`Period.of_days(1)`), or
from a `datetime.timedelta`.
- Immutable, hashable and sortable, so periods work as dictionary keys, in sets, and in order of length.

### Offsets and origins

- **Offsets** shift every interval boundary off its natural position, written as `<duration>+<offset>` - an
extension of the ISO 8601 duration format - so a hydrological day (`"P1D+T9H"`) or a water year (`"P1Y+9MT9H"`)
becomes a value that can be stored and passed around.
- **Origins** pin the grid to a chosen datetime, with the `"2024-01-01/P7D"` form.

### Intervals and ordinals

- Every interval on the timeline carries an integer **ordinal**
- `ordinal()` and `datetime()` map between timestamps and intervals, and are inverses of one another.
- `floor()` snaps a timestamp to its interval start, `interval()` gives that interval's half-open bounds, and
`range()` walks every interval overlapping a window of time.

### Comparison and alignment

- `is_aligned()` checks that a timestamp sits exactly on a period boundary - the check to run on incoming data
before trusting its claimed resolution.
- `is_subperiod_of()` reports whether one period's intervals nest cleanly inside another's, and `count()` gives how
many fit where that number is constant.
- `is_epoch_agnostic()` identifies periods that split the timeline the same way whatever epoch is used.
