# 1.1.0

A minor release covering how a `Period` renders itself. `str()` now represents periods that carry an origin,
and `repr()` reports a time zone accurately.

The documentation was also reworked so that every example is executed and its real output published alongside it.

## Changed

### `str()` format

A period built with an origin previously rendered as its duration and derived offset, which discarded the origin and so
could not be parsed back. It now renders in the `<origin>/<duration>` form it was built from:

|                                            | 1.0.0       | 1.1.0                         |
|--------------------------------------------|-------------|-------------------------------|
| `str(Period.of("2024-01-01/P7D"))`         | `"P7D+1D"`  | `"2024-01-01/P7D"`            |
| `str(Period.of("1883-01-01T09:00/P1D"))`   | `"P1D+T9H"` | `"1883-01-01T09:00:00/P1D"`   |
| `str(Period.of("2024-02-29T09:30/PT15M"))` | `"PT15M"`   | `"2024-02-29T09:30:00/PT15M"` |

`Period.of(str(period)) == period` now holds for every period.

### `repr()` is the string form plus the time zone

`repr()` now adds nothing to `str()` beyond the time zone, and only when there is one:

|                | 1.0.0             | 1.1.0            |
|----------------|-------------------|------------------|
| naive          | `PT15M[]`         | `PT15M`          |
| UTC            | `PT1H[Z]`         | `PT1H[Z]`        |
| fixed offset   | `PT1H[+05:30]`    | `PT1H[+05:30]`   |
| with an origin | `P7D+1D[]-105555` | `2024-01-01/P7D` |

## Fixed

- **A named time zone reported the offset it used in the nineteenth century.** The offset was sampled at
  `datetime.min`, so `repr()` of a period at `Europe/London` gave `P1D[-00:01:15]`, its Local Mean Time before standard
  time was adopted. A `zoneinfo.ZoneInfo` is now identified by its key: `P1D[Europe/London]`.
- **Two different periods could share a `repr()`.** A `tzinfo` whose `utcoffset()` returns `None` - which
  `datetime` permits - rendered as `PT1S[]`, identical to a naive period. Such a zone is now named after its class, so
  no two unequal periods render alike.

## Documentation

- Every example in the user guide is now executed when the documentation is built, and the output shown beneath it is
  what that code produced rather than something written by hand. The code lives in `docs/source/examples/`, is linted
  and type checked with the rest of the project, and is run by the test suite.
- Docstring examples use standard `>>>` doctests, collected by pytest, so a changed return value fails the build.
